# Настройка

Всё, что ниже, настраивается **данными** — через интерфейс администратора или API. Код менять не нужно.

## 1. Параметры сборки (`.env`)

| Переменная | Значение | Что делает |
|---|---|---|
| `VITE_API_BASE_URL` | `/api` | базовый адрес API; при прокси nginx/IIS — относительный путь |
| `VITE_USE_MOCKS` | `true` / `false` | `true` — запросы обслуживают моки в браузере (демо), `false` — реальный бэкенд; код моков в сборку не попадает |

Для сервера держите отдельный `.env.production`. Размещение не в корне сайта — `base` в `vite.config.ts`.

## 2. Пользователи и роли — «Администрирование»

- **Пользователи:** ФИО, логин, должность, вход (локальный или LDAP), срок действия учётной записи,
  статус (активен / заблокирован / удалён), **назначения** «роль → область».
  Удалить можно только того, кто не фигурирует в журналах; иначе — статус «удалён».
  «Сбросить пароль» выдаёт временный пароль, который нужно сменить при входе.
- **Роли** — шаблоны прав. Матрица: Справочники, Классификаторы, Заявки, Администрирование,
  Журнал действий × просмотр / создание / изменение / удаление / настройка / согласование.
  Для справочников — **ограничение колонок** (пример — «Кладовщик» без цены) и **строк** (фильтр по значению атрибута).
  Где действует роль, решает назначение: вся система, справочник или классификатор.
- **Парольная политика:** длина, классы символов, срок действия, число неповторяемых паролей.
  Пароли хранятся как SHA-512 с солью (`lib/security/password.ts`).

Готовые роли демо: Администратор, Руководитель службы НСИ, Модератор, Нормоконтролёр, Бухгалтер,
Кладовщик, Пользователь, Аудитор.

## 3. Справочники — «Справочники → карточка → Структура / Классификаторы / Согласование»

- **Структура:** атрибуты (целое, дробное, строка, дата-время, файл, составной, ссылка на другой
  справочник), обязательность, шаблон, длина, мин/макс, ширина колонки, показ в таблице;
  атрибут-наименование; иерархия (группы); набор **состояний** с начальным.
- **Классификаторы:** какие классификаторы привязаны, в каком их каталоге подбирается шифр,
  обязателен ли шифр, предлагать ли краткое наименование шифра как наименование элемента.
- **Согласование** — три обходных листа: «Пополнение», «Корректировка», «Шифр из карточки».
  - строка: вид (Проверка / Шифрование), название, **роль** ответственного, атрибуты на проверку или классификатор;
  - **Только для групп** — строка действует для позиций из выбранных групп (с подгруппами);
  - **Срок, ч** — норматив; просрочка видна в заявках и на главной;
  - порядок: параллельно или по порядку; необязательная строка шифрования допускает «Не применимо»;
  - пустой лист — изменения применяются сразу.

Кто отвечает за строку: строка **Проверки** — владельцы её роли в области справочника; строка
**Шифрования** — владельцы роли в области классификатора строки. Глобальное назначение покрывает обе.

## 4. Классификаторы — «Классификаторы → карточка»

- **Свойства и фасеты:** направление чтения (справа налево по ТЗ / слева направо), режимы ввода
  (строкой, по фасетам), допустимые символы, смысловые блоки; фасет — длина (фиксированная /
  до разделителя / остаток шифра), тип, обязательность, список значений, подсказка.
- **Правила зависимостей** у фасета-триггера: при значении (или условии из 12 типов) меняют подпись,
  список значений и видимость **последующих** фасетов. Невидимый фасет не занимает места в шифре.
- **Структура:** дерево «корень → каталоги → ноды»; ветвление по условию перехода на значении фасета
  родителя, иначе — ветка по умолчанию.
- **Расшифровка:** шаблоны с условиями и частями (значение фасета, код, «подпись + значение», текст,
  префикс/суффикс); краткое наименование по шаблону `{facet}`, `{facet:code}`, необязательные блоки `[…]`.
- **Согласование** новых записей классификатора.

## 5. Интеграции — «Система → Интеграции»

- **Система:** включение обмена, адрес (`endpoint`), протокол, подпись внешнего ID; «Проверить связь».
- **Поток:** направление (выгрузка / загрузка), справочник, запуск (при изменении и/или по расписанию:
  ежечасно / ежедневно / еженедельно), фильтр состояний, обязательные утверждённые шифры,
  **сопоставление полей** «поле MDM → поле системы» с признаком обязательности;
  для загрузки — «через заявку модераторам» или «сразу в справочник».
- **Журнал обмена:** фильтры по системе и статусу; ошибки видны и в карточке элемента.

Настроенный демо-набор: номенклатура → 1С и АСУ, контрагенты ← 1С (сразу), стандартные изделия ←
Imbase (через заявку), шифры инструмента → Imbase.

## 6. Демо-данные (только `VITE_USE_MOCKS=true`)

- Исходный набор — `src/mocks/data/*`: справочники (`catalogs.ts`), классификаторы (`classifiers/*`),
  пользователи и роли (`users.ts`), шаблоны листов, заявки, журнал (`requests.ts`), интеграции (`integrations.ts`).
- Шифры элементов в данных расшифровываются движком при загрузке (`seedCode`) — неверный шифр сразу
  даёт ошибку, а тест `mocks.spec.ts` проверяет весь набор.
- Изменения пользователей сохраняются в браузере; при изменении исходных данных в коде старая копия
  автоматически не используется. Сброс — «Администрирование → Сбросить демо-данные».
