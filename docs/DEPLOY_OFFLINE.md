# Выкатка на компьютер без интернета

Есть три сценария — выберите свой:

| Сценарий | Что нужно на целевом ПК | Для чего |
|---|---|---|
| **A. Офлайн-пакет (демо-стенд)** | Windows 10/11 *или* Linux с `python3`, любой современный браузер | показать, обучить, проверить настройки; один пользователь на ПК |
| **B. Разработка в закрытом контуре** | Node.js ≥ 20.19 (22 LTS) | дорабатывать код без интернета |
| **C. Сервер в контуре** | nginx или IIS + бэкенд по контракту `docs/API.md` | рабочая многопользовательская система |

---

## A. Офлайн-пакет

Готовый архив `mdm-nsi-offline-<версия>.zip` лежит в **GitHub Releases** репозитория
(или собирается командой `npm run bundle:offline` → `release/`).

### Установка

1. Скопируйте zip на флешку → на целевой ПК → распакуйте в любую папку (например `C:\MDM`).
   Права администратора не нужны.
2. **Windows:** дважды щёлкните `start-windows.cmd`. Откроется окно сервера и браузер с
   `http://localhost:8080/`. Окно сервера не закрывайте, пока работаете.
3. **Linux / macOS:** `chmod +x start-linux.sh && ./start-linux.sh` → откройте `http://localhost:8080/`.
4. Войдите, например `admin` / `admin` (полный список — в `ПРОЧТИ.txt` и README).

Состав пакета:

```
mdm-nsi-offline-<версия>/
  app/                 собранное приложение (HTML, JS, CSS, шрифты, иконки — всё локально)
  start-windows.cmd    запуск на Windows (вызывает serve.ps1)
  serve.ps1            мини-сервер на PowerShell 5.1 (входит в Windows), SPA-маршруты → index.html
  start-linux.sh       запуск на Linux/macOS (вызывает serve.py)
  serve.py             мини-сервер на стандартной библиотеке Python 3
  nginx.conf, web.config  примеры для серверной выкатки (сценарий C)
  docs/                эти инструкции
  ПРОЧТИ.txt           памятка
```

### Почему нужен мини-сервер, а не двойной щелчок по index.html

Демо-данные обслуживает **service worker** (MSW): браузер разрешает его только на `http://localhost`
или по HTTPS, а с `file://` — нет. Поэтому `serve.ps1` / `serve.py` поднимают локальный сервер
только на `localhost`; из сети к нему не подключиться.

### Где хранятся данные демо

В `localStorage` браузера на этом ПК (ключ `mdm.demo-db`): заявки, правки, пользователи и журнал
переживают перезапуск. У каждого браузера и профиля Windows — своя копия.
Сброс: **Администрирование → «Сбросить демо-данные»**. Новая версия пакета с изменёнными
демо-данными сама начинает с чистого набора.

### Проверка пакета перед выдачей

На машине разработчика: распакуйте архив, запустите `start-windows.cmd`, затем

```bash
npm run smoke:offline -- http://localhost:8080/
```

Обычный Chromium войдёт под `admin` и найдёт позицию в справочнике (`OK: вход и справочник работают`).

### Обновление

Распакуйте новый архив рядом (или поверх папки `app/`) и запустите снова. Если браузер показывает
старую версию — `Ctrl+F5`.

### Неполадки

| Симптом | Что сделать |
|---|---|
| «Port 8080 is busy» | `start-windows.cmd -Port 8081` / `./start-linux.sh 8081` |
| Окно мигнуло и закрылось | Запустите из `cmd`: `powershell -ExecutionPolicy Bypass -File serve.ps1` — увидите ошибку. Запрет скриптов групповой политикой → попросите ИТ разрешить `serve.ps1` или используйте `serve.py` |
| Белая страница, в консоли браузера «Failed to register a ServiceWorker» | Откройте именно `http://localhost:…`, а не IP-адрес или `file://` |
| Не входит под пользователем | Проверьте раскладку; пароль демо = логин (LDAP-пользователи — `ldap`) |
| Данные «пропали» | Другой браузер/профиль, либо очищены данные сайта. Это демо: рабочие данные — только на сервере (сценарий C) |

Поддерживаемые браузеры: Chrome/Chromium/Яндекс.Браузер ≥ 110, Edge ≥ 110, Firefox ≥ 115.

## B. Разработка без интернета

Проект собран так, чтобы после копирования работать в закрытом контуре:

- **Нет CDN.** Шрифт Manrope (`@fontsource-variable/manrope`), иконки (`primeicons`), тема PrimeVue — из `node_modules`.
- **MSW-воркер** лежит в `public/mockServiceWorker.js` (в репозитории).
- **Chromium для e2e** ставится внутрь `node_modules` (`PLAYWRIGHT_BROWSERS_PATH=0`), `npm run test:e2e` в сеть не ходит.
- **Версии зафиксированы** (`save-exact` в `.npmrc` + `package-lock.json`).

Подготовка на машине **с интернетом** (той же ОС и разрядности, что и целевая):

```bash
git clone <url репозитория> mdm-nsi && cd mdm-nsi
npm ci
npm run e2e:install
npm run ci
```

Перенесите **всю папку вместе с `node_modules`** (~0.9 ГБ, из них ~0.5 ГБ — Chromium) и установщик
Node.js 22 LTS. В `node_modules` есть нативные бинарники (esbuild, rollup) — поэтому ОС сборочной и
целевой машины должны совпадать.

Альтернатива без копирования `node_modules` — офлайн-кеш npm:

```bash
npm ci --cache ./npm-cache          # на машине с интернетом
npm ci --offline --cache ./npm-cache   # на целевой машине
```

В контуре с локальным зеркалом npm (Nexus, Verdaccio) достаточно `npm config set registry <url зеркала>` и `npm ci`.

Проверка после переноса: `npm run ci` и `npm run test:e2e`. Запуск: `npm run dev` → `http://localhost:5173`.

## C. Сервер в закрытом контуре

1. Соберите фронтенд без моков:

   ```bash
   # .env.production
   VITE_USE_MOCKS=false
   VITE_API_BASE_URL=/api
   ```

   ```bash
   npm run build      # результат — dist/
   ```

   При `VITE_USE_MOCKS=false` код моков в сборку не попадает.

2. Разместите `dist/` на веб-сервере:
   - **nginx** — пример `deploy/nginx.conf` (HTTPS, SPA-маршруты, кеш ассетов, прокси `/api` на несколько экземпляров бэкенда);
   - **IIS** — пример `deploy/web.config` (нужны модули URL Rewrite и ARR, ставятся офлайн-установщиками).
3. Бэкенд реализует контракт из `docs/API.md`. Как его масштабировать — `docs/SCALING.md`.
4. HTTPS обязателен для рабочей системы: сертификат внутреннего УЦ предприятия.

Приложение можно разместить не в корне сайта (`https://portal/mdm/`): задайте `base: '/mdm/'` в
`vite.config.ts` — роутер и путь к service worker уже берут его из `import.meta.env.BASE_URL`.
